# 첫 방문·뉴트럴 포즈·가을 네 시간대

**가을의 맑은 새벽·낮·노을·밤에서 처음 한 번, 이후 약 5분마다 다가온다.**
다른 행동과 영상 속 팔 동작이 끝나 뉴트럴 포즈가 되어야 출발하며,
다가오는 동안 그 포즈를 유지한다. 네 시간대의 앞꽃·잔디·이동 그림자를 연결했다.
확대 화질은 원본 576×496의 한계가 크다. 고해상도 뉴트럴 그림을 별도로
준비해 같은 DOM 모션에 얹는 방법을 권한다. 이번 변경에는 고해상도 자산 제작은
포함하지 않았으며, 기존 자산 80개와 판번호는 유지했다.

## 방문 조건

- 첫 장면이 준비되면 뉴트럴 포즈를 확보하고 배경 페이드가 끝난 뒤 방문한다.
  새로고침하면 다시 첫 방문을 한다. 처음부터 정지 모드면 접근하지 않는다.
- 이후 실제 접근 시작부터 5분을 센다. 5분이 되어도 공·나비·폴짝·졸기·
  기지개·표정 기호 또는 영상의 팔 동작이 진행 중이면 기다린다.
- 설정 창이 열려 있을 때도 기다린다. 수동 호출과 집중 종료는 같은 조건을
  사용하고, 중복 요청은 한 번으로 합친다.
- 접근 4.2초 → 근접 인사 2.4초 → 복귀 3.4초. 돌아가기·내루미 클릭·Escape로
  일찍 돌아갈 수 있다.
- 탭 숨김·장면 변경·화면 크기 변경·동작 줄이기는 포즈 고정과 모션을 해제한다.
  탭 복귀·장면 전환·움직임 재개에서는 새로 5분을 센다. 아직 첫 인사를 하지
  않았다면 허용된 장면에서 첫 인사를 먼저 한다. 숨은 동안의 방문은 누적하지 않는다.
- 비 오는 가을과 다른 계절은 이번 확장 범위에 포함하지 않았다.
  해당 풍경의 집중 종료는 기존 문구·폴짝 인사, 정지 모드는 문구로 알린다.

미리보기는 다음 주소에서 `v`만 `dawn`, `day`, `dusk`, `night`로 바꾼다.
`act=approach`는 한 번만 실행한다. 5분 반복은 `act`를 빼고 확인한다.

```text
/?s=autumn&v=night&w=clear&act=approach&ball=0&flit=0&ff=0
```

## 뉴트럴 포즈와 레이어

`window.naeru.isNeutral()`은 busy·hold, 표정 기호, 이동·몸짓 transform을
함께 확인한다. 영상 속 행동은 이 상태와 별개이므로 활성 영상의 재생 위치도
확인한다. 24fps·316프레임 루프에서 처음·끝 8프레임의 팔을 내린 구간만 허용한다.
영상을 강제로 되감거나 탐색하지 않고 자연스럽게 도달한 프레임에서 일시 정지한다.
영상 재생 위치만으로는 DOM 몸짓 여부를 알 수 없으므로 두 조건을 모두 지킨다.

접근이 포즈를 소유하는 동안 `data-pause-owner="approach"`를 지정해 플레이어의
재생 실패 감시와 구분한다. 복귀·중단 시 소유권과 busy·hold를 해제하고, 보이는
장면에서 움직임이 허용되면 영상 재생을 이어간다. 첫 장면의 정지본→영상 확정이
두 번 발생해도 첫 방문 요청이 중복되지 않는다.

꽃 마스크의 형상은 `bg-day-autumn.jpg`에서 구하고 실제 꽃·잔디 픽셀은
현재 시간대의 배경에서 가져온다. 네 그림의 꽃 위치는 같다. 밤 그림 자체에
낮용 밝기 임계를 적용해 꽃이 사라지는 문제를 피한다. 공통 마스크 이미지를
미리 로드하고 실패하면 확대 대신 기존 인사로 처리한다.

출발점에 구워진 그림자는 같은 시간대의 잔디 패치로 가린다. 별도 이동 그림자는
새벽·노을·밤의 명암에 맞춰 약하게 표시한다. 원본 배경과 캐릭터 크롭 좌표는
그대로다. 앞꽃은 기존 색상 마스크를 확장한 시범 합성이라 작은 꽃잎 가장자리와
줄기에는 거친 부분이 남아 있다. 정교한 근접 그림 제작 시 함께 다듬을 대상이다.

## 확대 화질 조사

### DOM을 크게 만드는 것만으로는 부족하다

`ffprobe`와 제작 스크립트에서 확인한 원본 배경 영상은 3840×2160이고,
캐릭터는 그중 576×496 영역을 축소 없이 잘라낸 영상이다.
`tools/naeru-split/build.sh`의 `CROP="576:496:1744:1328"`과
`coords.py`, CSS 좌표가 이 계약이다. 큰 배경 원본이 있어도 그 안의 작은
캐릭터에 더 많은 픽셀이 생기지는 않는다.

1920×1080 화면에서는 크롭이 평상시 288px 폭으로 표시되고 접근 때
약 9.88배, 즉 약 2844px 폭으로 늘어난다. 소스 대비 약 4.94배다.
얼굴 자체는 크롭 일부이므로 실제 눈·입의 원본 픽셀은 더 적다.
390×844 화면에서는 크롭 표시 폭이 근접 시 약 1264 CSS px가 되며,
DPR 3 화면은 약 3792 물리 픽셀에 그린다. 이 때문에 모바일에서도 흐릿하다.

### 브라우저와 압축 비교

동일한 뉴트럴 프레임·확대율을 고정하고 1920×1080 DPR 1 및
390×844 DPR 3에서 다음을 비교했다.

| 비교 | 관찰 |
|---|---|
| 기존 영상 + `will-change: transform` | 현재 근접 화면 |
| 위 상태에서 `will-change` 해제 | 눈에 띄는 선명도 개선 없음 |
| 같은 포즈의 압축 전 RGBA PNG | 압축 질감은 일부 줄지만 확대 흐림은 남음 |

Chrome의 공식 설명은 `will-change`가 확대 전 래스터를 재사용할 수 있고,
해제하면 다시 그리게 할 수 있다고 안내한다. 이번 페이지의 실제 영상 합성에서는
그 변경만으로 개선되지 않아 런타임 CSS는 유지했다.
[Chrome 렌더링 설명](https://developer.chrome.com/blog/re-rastering-composite)

이 관찰은 Chromium 151.0.7922.34의 결과다. Safari·iOS에서 같은 렌더링 경로라고
단정하지 않는다. 영상 압축 전 PNG도 같은 576×496이므로 고해상도 비교본은 아니다.

### 권장 제작 방식

**근접용 고해상도 뉴트럴 그림 + 현재 DOM 모션**이 우선이다.
다가오는 동안 포즈가 고정되므로 영상 전체 316프레임을 고해상도로 다시 만드는
비용을 먼저 들일 필요가 없다.

1. 현재 실루엣·눈·혀·발끝 좌표를 보존한 투명 뉴트럴 마스터를 제작한다.
   4배인 2304×1984부터 비교하고, 큰 화면·DPR 3에서는 더 높은 해상도가
   필요한지 확인한다. 단순 리사이즈가 아니라 선과 경계를 복원한 원본이어야 한다.
2. 새벽·낮·노을·밤의 색을 맞춘 파생본을 만든다. 가까워지기 전에 로드·디코드한다.
   파일 용량과 알파 가장자리 품질을 함께 보고 PNG 또는 WebP를 선택한다.
3. 먼 거리의 원래 영상에서 근접 그림으로 자연스럽게 전환한다. 현재 뉴트럴
   허용 구간에도 미세한 포즈 차이가 있으므로 실제 프레임과 좌표를 대조해야 한다.
   단순 교체만 하면 눈·혀·몸 경계가 튈 수 있다.
4. 기존 `#naeru-approach`·`#naeru-stride` 모션으로 확대·보폭을 적용하고,
   복귀 후 원래 영상을 이어간다. 이 방식은 현재 구조에 대한 제안이며 아직 미구현이다.

복원 후보인 Real-ESRGAN의 공식 애니메이션 모델은 4배 확대를 제공한다.
원본과 나란히 비교해 얼굴과 선이 보존되는지 평가할 수 있다.
이 프로젝트에서는 해당 모델을 실행하거나 결과 품질을 검증하지 않았다.
[공식 애니메이션 모델 문서](https://github.com/xinntao/Real-ESRGAN/blob/master/docs/anime_video_model.md)

전체 영상을 4배로 만들면 프레임당 픽셀 수가 16배가 된다. 네 시간대
316프레임을 처리하고 VP9·HEVC 알파 인코딩과 시간에 따른 선의 흔들림까지
다시 검증해야 한다. 가까이서도 계속 표정·팔을 움직이게 할 때 고려할 후속 작업이다.

## 검증과 산출물

전체 Chromium 회귀 검사 **20/20 통과**. 자산 80개·크롭 좌표·자산 판번호·
경로 보호, 인라인 JavaScript 10개 문법, 문서 링크, `git diff --check`도 통과했다.
화면 비교 페이지의 장면 24장·화질 비교 6장과 모바일 레이아웃을 확인했다.

실제 영상에서 몸짓과 팔 동작을 기다리고, 탐색 없이 포즈를 고정한 뒤
재생을 복구하는 검사를 추가했다. 가상 시계 검사는 첫 방문, 5분 전 방문 방지,
5분 이후 비뉴트럴 포즈 대기, 실제 출발부터 다음 주기 계산, 숨은 탭의 방문
누적 방지를 확인한다. 가상 시계가 네이티브 영상 시간을 진행시키지 않으므로
이 검사에서만 영상 시간·재생 이벤트를 제어하고 실제 영상 검사를 별도로 유지한다.
