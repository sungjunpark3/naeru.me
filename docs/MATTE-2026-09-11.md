# 내루미 누끼 점검과 발끝 복원

**머리·상체의 분리는 유지하고, 일부 잘리고 반투명해졌던 발톱을 복원했다.**
원본 316프레임을 다시 처리해 8가지 색상의 WebM·HEVC·정지본을 갱신했다.
두 영상 형식의 알파 5,056프레임 검사와 기존 합성 품질 검사를 통과했다.
현재 로컬 파일에 반영했으며 커밋·배포는 하지 않았다.

## 발견과 수정

원본, PNG 시퀀스, 실제 WebM을 검정·흰색 바탕과 확대 화면에서 비교했다.
발톱의 밝은 부분이 원본보다 작아지고 색이 흐려지는 현상이 확인됐다.

발밑 배경은 캐릭터를 지우면서 다시 그린 잔디다. 이 구간에서 원본과 복원
배경의 차이를 피복률로 사용하면 밝은 발톱의 불투명도가 과소 추정된다.
`matte.py`에서 접지부는 잔디 색으로 분리한 실루엣을 사용하고,
밝고 중성인 발톱 색에만 작은 보정을 더했다. 전체 임계를 낮추는 후보는
배 아래의 잔디까지 포함해 채택하지 않았다.

상단에는 기존 피복률 계산을 유지하고 세로 구간으로 부드럽게 연결했다.
정지본과 혀 동작용 자산도 같은 시퀀스로 다시 만들고 자산 판번호를 갱신했다.
배경과 접지 그림자는 이 작업에서 다시 만들지 않았다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| PNG 원본 시퀀스 8×316프레임 | 평균 합성 PSNR 41.27dB, 최악 33.13dB, 기존 기준 통과 |
| WebM 합성 8×316프레임 | 평균 PSNR 39.98dB, 최악 32.94dB, 기존 기준 통과 |
| WebM·HEVC 16개 | 576×496, 24fps, 각 316프레임 확인 |
| 인코딩 알파 5,056프레임 | 프레임 가장자리 20px에 알파 8 초과 화소 없음 |
| 머리·상체 알파 | 크롭 y<300에서 316프레임 모두 이전과 화소 단위 동일 |
| 정지본·혀 자산 포함 런타임 자산 80개 | 크기·파일·좌표·내용 해시 검사 통과 |

발끝 보존은 원본 노을 영상에서 위치와 색으로 지정한 **18,495개 화소·프레임**을
기준으로 비교했다. 그중 알파가 200/255 미만인 수는 다음과 같다.
이는 전체 누끼 정확도 점수가 아니라 발톱 잘림의 회귀 검사다.

| 형식 | 수정 전 | 수정 후 |
|---|---:|---:|
| PNG 시퀀스 | 6,830 | 546 |
| WebM | 6,701 | 536 |
| HEVC | 6,837 | 549 |

같은 원본에서 확실한 잔디로 판별한 화소 중 알파가 128 이상인 수는
수정 전후 모두 2개였다. 검증한 영상에는 128 기준으로 둘러싸인 1화소 크기의
압축 흔적이 소수 남지만, 큰 내부 구멍이나 프레임 가장자리 오염은 없었다.

WebM은 알파를 지원하는 `libvpx-vp9` 디코더로, HEVC는 macOS AVFoundation으로
실제 알파를 추출했다. 일반 FFmpeg HEVC 디코딩만으로는 알파 검증을 대체하지
않았다. Apple의 [HEVC 알파 처리 설명](https://developer.apple.com/documentation/avfoundation/using-hevc-video-with-alpha)을 참고했다.

실제 페이지에서는 겨울 낮·노을·밤·강수, 여름 낮·노을, 모바일의 7개 조건에서
WebM 재생과 폴짝 동작을 확인했다. 확인한 화면에서 바닥에 남은 발이나 캐릭터
조각은 없었고 접지 그림자가 남았다.

## 재현과 해석 범위

변경 코드는 `tools/naeru-split/matte.py`의 `grass_cap()`과
`build_alpha_sequence()`다. 기존 입력 프레임에서 매트를 다시 만들고,
`build.sh`의 기존 VP9·HEVC 인코딩 설정과 `tongue.py`를 사용했다.
이번 실행은 검사 폴더에서 Pillow와 화소 결과가 동일함을 확인한 OpenCV
연산으로 flood fill·최대/최소 필터만 가속했다. 저장소의 제작 알고리즘이나
필수 의존성은 이 가속 때문에 바꾸지 않았다.

원화의 부드러운 윤곽과 빠른 동작의 기존 시간축 평활은 유지했다.
풀에 가려 원본에 존재하지 않는 발 모양을 새로 그린 작업은 아니다.
HEVC 알파 데이터 검증은 Safari/iOS 실기기의 화면 합성 검증과는 별개다.
